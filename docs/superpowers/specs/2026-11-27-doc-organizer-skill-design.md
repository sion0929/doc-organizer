# doc-organizer Skill 설계서

- 작성일: 2026-11-27
- 상태: 승인됨 (사용자 "진행")

## 1. 목적

SUVLab(대학 연구실, 국가과제 수행) 팀원이 자료를 노션에 정리할 때 쓰는 Claude Skill.
Claude가 **어떤 자료를 정리하는지 묻고**, 자료가 있으면 **초안을 쓰고 빈 곳만 질문**,
자료가 없으면 **양식에 따라 질문**해서, **팀 노션에 복붙했을 때 형식이 정확히 유지되는**
마크다운을 만들어 준다.

팀 노션은 Claude와 연결되지 않으므로 결과물은 전부 **복사 → 붙여넣기**로 옮긴다.

### 범위 밖

- 문서 정리 메뉴얼(저장 위치·파일명 규칙·작성 주기 등 운영 규칙) → 별도 작업
- 노션 API 자동 입력, 엑셀(.xlsx) 파일 생성

## 2. 사용자와 환경

- 사용자: 당장은 사용자 본인(Claude Code). 나중에 팀원이 claude.ai에서도 쓸 수 있도록
  양식은 환경에 묶이지 않게 작성한다(질문 도구가 없으면 번호 목록으로 묻기 등).
- 노션 구조는 새로 만든다. 유형마다 데이터베이스(DB) 1개.

## 3. 핵심 원칙: 구조만 기록

사용자가 준 참고 자료(논문·특허·시험일지·회의록·구매 엑셀)에서 **구조만 뽑아** 양식으로 만든다.
양식 파일에는 실제 내용(과제명, 금액, 수치, 발명 내용 등)을 **절대 남기지 않는다.**
내용은 사용할 때마다 사용자에게서 받는다.

### 양식 파일 공통 구성

각 양식 파일은 다음 네 부분으로 이루어진다. 노션 DB 설정 가이드는 ①을 참조한다(원본 하나).

1. **노션 DB 속성** — 속성 이름 / 노션 속성 종류 / 선택지
2. **질문 목록** — 섹션별, 필수/선택 구분
3. **본문 뼈대** — 노션에 붙여넣을 마크다운 골격 (제목 수준은 사용자가 쓰던 그대로)
4. **작성 메모** — 해당 유형만의 주의점

### 4.1 특허 초안 (`patent-draft.md`) — 제목 수준 `##`

DB 속성: 발명 명칭(제목) · 상태(선택: 아이디어/초안 작성/발명신고/출원/등록/보류) · 발명자 · 관련 과제 · 출원번호 · 마감일

본문:
1. `## 발명 명칭` — 국문 / 영문
2. `## 발명의 배경` — 기술 분야 서술 → **기존 기술의 문제점**(번호 목록) → **개발 배경**
3. `## 발명의 내용` — 해결 수단(번호 목록) → 📷 전체 도면 → 상태별 설명(`**상태명**: 설명` 반복)
4. `## {구성요소 이름} ({도면부호})` — **N개 반복**. 각각 📷 도면 / 구성(도면부호 포함) / 동작 원리 / 의도한 효과
5. `## 동작 과정` — 단계별 번호 목록(`**단계명**: 설명`) → 원리 보충 설명
6. `## 발명의 효과` — 번호 목록
7. `## 주장하려는 권리` — Claude 제안 시 `(초안 — 변리사 검토 필요)` 표시
8. `## 발명의 용도` — `**용도**: 설명` 목록
9. `## 선행기술 및 참고자료`

### 4.2 선행특허 조사 (`patent-prior-art.md`) — 제목 수준 `##`

DB 속성: 발명 명칭(제목) · 특허번호 · 출원인 · 국가(선택: KR/US/EP/JP/CN/WO/기타) · 출원일 · 공개·등록일 · 법적 상태(선택: 공개/등록/거절/소멸/기타) · 관련도(선택: 상/중/하) · 관련 우리 발명 · 링크

본문: `## 요약` → `## 대표 청구항`(원문 인용 `>`) → `## 핵심 구성` → `## 우리 발명과 비교`(표: 구성요소 | 선행특허 | 우리 발명 | 차이) → `## 차별화·회피 포인트` → `## 메모`

### 4.3 논문 작성 (`paper-writing.md`) — 제목 수준 `###`

DB 속성: 논문 제목(제목) · 상태(선택: 구상/작성 중/내부 검토/투고/리비전/게재 확정/게재) · 투고처 · 투고 마감일 · 저자 · 관련 과제 · 버전

본문 (들여쓰기 목록 위주):
1. `### 제목` — 버전별(초안 제출본 / 현재 작성본 …)
2. `### 서론` — 연구배경 / 기존 방법 및 한계(하위: 기존 방법들, 한계) / 제안 프레임워크 개요 / 기여점
3. `### Problem Formulation` — 문제 환경·주어진 조건 / 목적(목표·제약) / 전체 프레임워크 단계
4. `### 제안 방법` — 📷 전체 구조도 → 모듈별 설명(하위 목록)
5. `### 실험` — 실험환경(📷) → 검증 실험 N개(각각 📷 / 비교 대상 / 평가 지표)
6. `### 결론` (선택)

### 4.4 논문 리뷰 (`paper-review.md`) — 제목 수준 `###`

DB 속성: 논문 제목(제목) · 저자 · 게재처 · 연도 · 링크/DOI · 분야 태그(다중 선택) · 관련도(상/중/하) · 리뷰어 · 리뷰일

본문: `### 한 줄 요약` → `### 문제 정의` → `### 제안 방법`(📷 핵심 그림) → `### 실험`(환경·데이터 / 비교 대상 / 지표 / 주요 결과 표) → `### 기여점` → `### 한계` → `### 우리 연구와의 관련성`(활용할 점 / 차이점 / 인용할 부분 `>` + 쪽수) → `### 더 읽어볼 레퍼런스`

### 4.5 개발 문서 (`dev-doc.md`) — 제목 수준 `#`

DB 속성: 문서 제목(제목) · 대상 시스템 · 문서 종류(선택: 설계/구현/사용법/트러블슈팅) · 작성자 · 상태(선택: 작성 중/검토/완료) · 관련 과제

본문: `# 개요`(목적·범위·관련 시스템) → `# 요구사항` → `# 시스템 구성`(📷 구조도 + 표: 구성요소 | 역할 | 입력 | 출력) → `# 상세 설계 및 구현`(`### 모듈별`) → `# 사용 방법`(환경 / 설치 / 실행 코드 블록 / 파라미터 표) → `# 이슈 및 해결`(문제 → 원인 → 해결) → `# 변경 이력`(표: 날짜 | 변경 내용 | 작성자) → `# 참고 자료`
문서 종류에 따라 필요 없는 섹션은 뺀다.

### 4.6 시험일지 (`test-log.md`) — 제목 수준 `#`

DB 속성: 시험명(제목) · 시험일 · 장소 · 참여자 · 관련 과제 · 시험 대상 시스템(다중 선택) · 결과(선택: 성공/부분 성공/실패)

본문:
1. `# 시험내용` — 시험 항목 목록, 하위에 세부 내용·변경점
2. `# 시험결과` — `### 서브시스템별` 반복. 결과 목록 / 📷·🎞 자료 / 참고 링크 / `결론:`
3. `# 분석` — 발견 사항 목록, 하위에 근거 + 📷
4. `# TODO` — 다음 시험 계획(날짜), 차선책
5. `# LOG` — 데이터 종류별(rosbag, ulog, 영상 등) 파일명 + `📎 노션에서 직접 첨부`

### 4.7 회의록 (`meeting.md`) — 제목 수준 `#`

DB 속성: 회의명(제목) · 일시 · 참석자 · 회의 종류(선택: 정기/과제/행정/기타) · 관련 과제

본문: `# Agenda`(`- [ ]` 목록) → `# Budget`(선택: 예산 논의 시. 표: 과제 | 재료비 | 활동비 | 안전관리비 + 합계 행, 열은 조정 가능) → `# Meeting Summary`(안건별 목록) → `# Action Items`(`- [ ] 할 일 — 담당자 — 기한`)

### 4.8 구매물품 (`purchase.md`) — 표

열(= DB 속성, 엑셀 열 순서 유지): 할당 과제(선택) · 품목(제목) · 수량(숫자) · 단가(숫자, ₩) · 배송비(숫자) · 총 금액(숫자 = 수량×단가+배송비) · 세부사항(옵션) · 용도 · 구매 링크(URL) · 진행 상태(선택: 구매 요청/구매 진행/구매 완료/품절/취소)

- 품목 여러 개를 한 번에 받는다.
- 총 금액은 계산하되 계산식을 함께 보여주고, 노션에서는 수식 속성을 권장한다.
- 가격은 링크에서 추측하지 않고 사용자에게 받는다.

### 4.9 할 일 (`todo.md` + `todo/*.md`) — 제목 수준 `#`

흐름:
1. "어떤 일인가요?" — 6개 분류를 **체크박스로 다중 선택**(+기타)
2. 체크한 분류마다 그 분류 양식의 질문을 한다.
3. 결과는 **분류별 섹션**으로 나누고, 섹션마다 그 일에 맞게 쪼갠 **세부 할 일 체크리스트**를 넣는다.

## 5. 진행 흐름 (SKILL.md)

1. **유형 선택** — 번호 메뉴 1~7. 첫 메시지에 자료가 있으면 유형을 추정해 한 줄로 확인만 받는다.
   질문 도구(AskUserQuestion)가 있으면 그것을, 없으면 번호 목록을 쓴다.
2. **세부 유형** — 특허·논문만 (1-1/1-2, 2-1/2-2). 할 일은 분류 다중 선택.
3. **양식 읽기** — 선택된 양식 파일만 읽는다.
4. **자료 확인** — "정리할 자료가 있으면 붙여넣거나 첨부해주세요. 없으면 질문으로 진행합니다."
   - 자료 모드: 초안 작성 → 빈 곳 `⚠️ 확인 필요` → **필수 항목만** 한 번에 질문(최대 5개) → 확정
   - 질문 모드: 섹션 단위로 2~4개씩 질문. "없음/건너뛰기" 허용
5. **출력** — 6장 형식
6. **검사** — 코드 실행이 가능하면 `scripts/check_notion_md.py`로 본문 검사, 위반 시 고쳐서 다시 출력
7. **수정** — 요청 반영 후 전체 다시 출력

## 6. 출력 형식

### 페이지 유형

```
**① 노션 속성 입력값** (DB 속성 칸에 직접 입력)
| 속성 | 값 |
|---|---|
| ... | ... |

**② 본문** (코드 블록 오른쪽 위 복사 버튼 → 노션 페이지 본문에 붙여넣기)
````markdown
(본문)
````
```

- 본문은 백틱 4개 코드 블록으로 감싼다(본문 안에 코드 블록이 있어도 깨지지 않게).
- claude.ai: 코드 블록의 복사 버튼은 원본 마크다운만 복사한다 → 노션이 변환.
- Claude Code: 터미널 화면 복사는 줄바꿈이 깨질 수 있으므로
  `notion-output/YYYY-MM-DD_유형_제목.md`에 본문을 저장하고, `xclip`/`wl-copy`/`pbcopy` 중 있는 것으로 클립보드에 복사한다.

### 표 유형 (구매물품)

- 화면에 마크다운 표로 보여준다. claude.ai에서는 표를 드래그해 복사하면 엑셀·노션에 셀 단위로 붙여넣어진다.
- Claude Code: `notion-output/YYYY-MM-DD_구매물품.csv`(UTF-8 BOM, 엑셀 한글 깨짐 방지) 저장
  → 엑셀로 열거나 노션 DB의 "CSV로 병합"에 사용.

## 7. 노션 복붙 규칙

| 쓴다 | 쓰지 않는다 |
|---|---|
| 제목 `#` `##` `###` | `####` 이하 제목 |
| 목록 `-`, 번호 `1.`, 들여쓰기(공백 4칸) | HTML 태그, `<details>`, `<br>` |
| 체크박스 `- [ ]` `- [x]` | 콜아웃, 토글 (붙여넣기로 변환 안 됨) |
| 표 (칸 안 줄바꿈 없음, 칸 안 `\|`는 `/`로 대체) | 수식 블록 `$$` |
| 코드 블록(언어 지정), 인용 `>`, 구분선 `---` | 각주, 이미지 문법 `![]()` |
| 굵게 `**`, 기울임 `*`, 인라인 코드, 링크 `[글](URL)` | 빈 줄 없이 제목·목록·표를 붙여 쓰기 |

- 그림: `📷 [그림: 설명 — 노션에서 직접 첨부]`
- 첨부 파일: `📎 [파일: 파일명 — 노션에서 직접 첨부]`
- 확인 안 된 값: `⚠️ 확인 필요` (번호·금액·날짜·수치·링크는 받은 그대로, 지어내지 않음)
- Mermaid 코드 블록은 노션 변환 검증 전까지 "검증 후 사용"으로 둔다.
