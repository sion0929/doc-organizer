# SUVLab Works 양식 (할 일 정리)

- 유형: 7. SUVLab Works (메뉴·파일명·DB 이름은 SUVLab Works, 본문의 "할 일"은 그대로)
- 출력: 페이지
- 제목 수준: 섹션 `#`, 하위 항목 `###`
- 구성: 이 파일(공통: DB 속성, 분류 고르기, 개요, 세부 할 일 쪼개기 흐름) + 체크한 분류의 양식 파일 `templates/todo/*.md`
- 용도: 해야 할 일을 "어떤 종류의 일인지"로 나누고, 분류마다 그 일에 맞게 쪼갠 세부 할 일 체크리스트로 정리한다.

## ① 노션 DB 속성

| 속성 | 종류 | 선택지 / 비고 |
|---|---|---|
| 할 일 이름 | 제목 | 예: 대상 + 할 일을 짧게 |
| 분류 | 다중 선택 | 실험 내용 정리 / 하드웨어 제작 내용 정리 / 시스템 설계 내용 정리 / 계획 구체화 구현 / 시스템 구조도 설계 / 점검 문서 작성 / 기타 |
| 담당자 | 사람 | 노션에서 직접 선택. 출력에는 이름만 적는다 |
| 마감일 | 날짜 | |
| 상태 | 선택 | 시작 전 / 진행 중 / 완료 / 보류 |
| 관련 과제 | 선택 | 과제명 |

## ② 질문 목록

- 이 파일의 1~4단계는 할 일 안의 단계다(SKILL.md의 단계 번호와 다르다). 분류 파일의 3-1, 3-2 … 는 이 파일 3단계의 하위 단계다.
- 1단계(분류 고르기) 메시지에 **자료 확인도 함께** 넣는다. 첫 메시지로 유형이 분명했으면 이 메시지가 유형 확인도 겸한다(따로 확인하지 않는다).
- 질문 모드의 목표 왕복은 **4번**이다.
    1. 분류 고르기 + 자료 확인
    2. 개요 필수(할 일 이름·목표·완료 기준) + 담당자·마감일·상태 + 체크한 분류들의 **필수** 질문
    3. 체크한 분류들의 **선택** 질문을 한 메시지에 모아 "있으면 적어주세요, 없으면 넘어갈게요" (배경·관련 과제 포함)
    4. 세부 할 일 확인
    - 분류를 3개 이상 골라 2번 메시지의 질문이 너무 많으면 2번을 둘로 나눠도 된다.
- 상태가 `시작 전`이면 진행 상황·결과·제작 중 문제·이상 사항을 묻는 질문은 하지 않는다.
- 첫 메시지나 앞선 답에 이미 나온 내용(대상, 기한 등)은 묻지 않고 채운다. 기한이 "다음 주까지"처럼 상대적이면 2번 메시지에서 마감일 날짜로 확인한다.
- 자료 모드에서는 1단계(분류 고르기)만 하고 **초안을 바로 출력한다**(SKILL.md 자료 모드). 2·3단계 질문과 4단계 세부 할 일 확인은 하지 않는다. 세부 할 일은 바로 본문에 넣고, ③ 확인할 것에 "세부 할 일 N개는 Claude가 나눈 것"이라고 적는다.
- 자료가 시스템·설계 내용이면(저장소, 설계서 등) 분류에 "시스템 구조도 설계"를 함께 넣어 아키텍처를 그린다(`templates/diagrams.md`).

### 1단계: 어떤 일인가요? (분류 고르기 — 체크박스, 여러 개 가능)

첫 메시지로 분류가 짐작되어도 체크박스로 묻는다(다른 분류가 섞여 있을 수 있다). 짐작한 분류가 있으면 질문 문구에 "○○ 같아 보입니다"라고 덧붙인다.

**질문 도구(AskUserQuestion 등)가 있을 때** — 질문 하나에 선택지가 4개까지라서, 다중 선택(`multiSelect: true`) 질문 2개를 **한 번의 호출**로 함께 보낸다.

- 질문 1 — 머리말 `정리·기록`
    - 문구: "어떤 일인가요? 해당하는 것을 모두 고르세요. 목록에 없으면 Other에 직접 적어주세요."
    - 선택지(이름 — 설명)
        - `실험 내용 정리` — 여러 날의 시험을 묶어 실험 전체를 종합
        - `하드웨어 제작 내용 정리` — 사양·부품·제작 과정·검증 기록
        - `시스템 설계 내용 정리` — 요구사항·설계 결정·인터페이스
        - `해당 없음` — 이 묶음에는 해당하는 일이 없음
- 질문 2 — 머리말 `설계·계획·점검`
    - 문구: "이어서, 해당하는 것을 모두 고르세요. 목록에 없으면 Other에 직접 적어주세요."
    - 선택지(이름 — 설명)
        - `계획 구체화 구현` — 목표를 단계별 실행 계획으로 만들고 진행
        - `시스템 구조도 설계` — 구성요소와 연결을 정리해 구조도로
        - `점검 문서 작성` — 점검 항목·기준·결과·조치 기록
        - `해당 없음` — 이 묶음에는 해당하는 일이 없음
- 기타: 도구가 자동으로 붙이는 Other(직접 입력)로 받는다. Other에 적은 글은 `기타`로 체크하고, 그 글을 기타 일 이름으로 쓴다.
- 질문 3 — 머리말 `자료` (첫 메시지에 자료가 이미 있거나 "없음"이라고 했으면 넣지 않는다)
    - 문구: "정리할 자료(메모, 엑셀, 사진 설명 등)가 있나요?"
    - 선택지: `없음 — 질문으로 진행` / `있음 — 다음 메시지에 붙여넣기`
- 두 질문의 답을 합친다. `해당 없음`은 버린다. 아무것도 고르지 않았으면 다시 묻는다.

**질문 도구가 없을 때** — 아래 목록을 그대로 보여주고 번호로 답하게 한다.

```
어떤 일인가요? 해당하는 번호를 모두 적어주세요(예: 1, 3).

- [ ] 1. 실험 내용 정리
- [ ] 2. 하드웨어 제작 내용 정리
- [ ] 3. 시스템 설계 내용 정리
- [ ] 4. 계획 구체화 구현
- [ ] 5. 시스템 구조도 설계
- [ ] 6. 점검 문서 작성
- [ ] 7. 기타 (어떤 일인지 한 줄로 적어주세요)

정리할 자료(메모, 엑셀, 사진 설명 등)가 있으면 같이 붙여넣어 주세요. 없으면 번호만 적어주시면 질문으로 진행합니다.
```

- 번호 대신 말로 답하면(예: "구조도랑 점검표") 해당 분류로 바꿔 한 줄로 확인받는다.
- 고른 분류는 노션 속성 "분류"의 값이 되고, 본문 분류 섹션의 목록이 된다.

### 2단계: 개요 (공통)

- **필수** 할 일 이름 — 무엇을 하는 일인지 한 줄
- **필수** 목표 — 이 일로 이루려는 것
- **필수** 완료 기준 — 무엇이 되면 끝났다고 할 수 있나요?
    - 답이 막연하면(예: "잘 되면") 확인할 수 있는 형태(결과물·수치·검토 통과 등)로 한 번 더 묻는다.
- 선택: 배경 — 왜 하는 일인지
- 선택: 담당자, 마감일, 관련 과제, 상태(시작 전 / 진행 중 / 완료 / 보류)

질문 모드에서는 필수 3개 + 담당자·마감일·상태를 2번 메시지에, 배경·관련 과제를 3번 메시지(선택 모음)에 넣는다.

### 3단계: 분류별 질문

체크한 분류의 양식 파일**만** 읽는다(체크하지 않은 분류의 파일은 읽지 않는다). 메뉴 순서대로 한 분류씩, 그 파일의 ② 질문 목록을 묻는다.

| 번호 | 분류 | 양식 파일 |
|---|---|---|
| 1 | 실험 내용 정리 | `templates/todo/experiment-summary.md` |
| 2 | 하드웨어 제작 내용 정리 | `templates/todo/hardware-build.md` |
| 3 | 시스템 설계 내용 정리 | `templates/todo/system-design.md` |
| 4 | 계획 구체화 구현 | `templates/todo/plan-implementation.md` |
| 5 | 시스템 구조도 설계 | `templates/todo/architecture-diagram.md` |
| 6 | 점검 문서 작성 | `templates/todo/inspection-doc.md` |
| 7 | 기타 | 파일 없음 — 아래 "기타를 골랐을 때" 질문과 이 파일 ③의 `# 기타` 뼈대 |

- 분류가 바뀔 때 "다음은 **{분류명}** 입니다"처럼 알린다.
- 개요나 앞 분류에서 이미 받은 답으로 채워지는 질문은 다시 묻지 않는다.

**기타를 골랐을 때**
- **필수** 어떤 일인가요? — Other(또는 7번)에 적은 글로 충분하면 다시 묻지 않는다
- 선택: 세부 내용, 지금까지 진행한 것

### 4단계: 세부 할 일 쪼개기 (분류마다 제안 → 확인)

1. 체크한 분류마다 그 분류 파일의 "세부 할 일 쪼개기 기준"과 사용자의 답으로 세부 할 일을 만든다. 기타는 아래 "기타 쪼개기 기준"을 쓴다.
2. 세부 할 일 한 줄 = `- [ ] {작업}` 에 필요할 때만 ` — {담당}` ` — {기한}` 을 붙인다.
    - 작업: "부품 목록 작성"처럼 짧은 작업 이름. 기준의 단계 이름을 그대로 쓰지 말고 답에 나온 대상(부품·조건·항목 이름 등)을 넣는다.
    - 담당: 개요 담당자와 **다른 사람**이 맡는 작업에만 쓴다(같은 사람이면 DB 담당자 속성으로 충분하다).
    - 기한: 사용자가 **그 작업의** 날짜를 말했을 때만 쓴다. 모르면 쓰지 않는다(`⚠️` 도 붙이지 않는다. 개요 마감일이 전체 기한이다).
    - 이미 끝난 작업은 지우지 않고 `- [x]`로 남긴다.
3. 크기: 분류마다 3~8개(사용자 답에 맞는 작업이 적으면 그보다 적어도 된다). 한 사람이 며칠 안에 끝낼 수 있는 크기로 나눈다. 더 잘게 나눌 작업은 하위 체크박스(공백 4칸 들여쓰기)로 둔다.
4. 사용자 답에 나오지 않고 분류 파일의 기본 순서에서 가져온 작업에는 확인 메시지에서만 `(기본 단계)` 표시를 붙인다(사용자가 빼기 쉽게). 답과 맞지 않는 기본 단계(예: "가공할 부품 없음")는 넣지 않는다.
5. 출력 전에 분류별로 묶어 **한 메시지에** 보여주고 확인받는다. 번호는 분류를 넘어 **이어서** 매긴다(“3번 빼줘”가 하나만 가리키게). 자료 모드에서는 필수 질문과 같은 메시지에 보여줘도 된다.

```
세부 할 일을 이렇게 나눠봤어요.

{분류명}
1. {작업}
2. {작업} — {다른 담당자} — {기한} (기본 단계)

{분류명}
3. {작업}

빼거나 더할 게 있으면 번호로 알려주세요(이미 끝난 작업, 다른 담당자·기한도).
그대로 좋으면 "좋아요"라고 답해주세요.
```

6. 답을 반영해 SKILL.md 4단계(출력)로 간다. "좋아요"로 확인된 작업에는 `(기본 단계)` 표시를 남기지 않는다. 작업을 많이 바꿨으면 바뀐 목록을 한 번 더 보여주고 확인받는다.

**기타 쪼개기 기준** — 준비(필요한 자료·도구·사람 확인) → 실행(사용자가 말한 작업을 단계별로) → 결과 확인 → 정리·공유. 사용자가 말한 내용에 맞게 빼고 더한다.

## ③ 본문 뼈대

- `{ }` 는 채울 자리. 출력에서는 내용으로 바꾸거나 `⚠️ 확인 필요` 로 둔다.
- `%% 반복: … %%` 아래 블록은 개수만큼 반복, `%% 선택: … %%` 아래 블록은 내용이 없으면 통째로 뺀다.
- `%% … %%` 줄 자체는 출력하지 않는다.

````markdown
# 개요

- 목표: {이 일로 이루려는 것}
- 배경: {왜 하는 일인지}
- 완료 기준: {기준이 하나면 이 줄에 바로 쓰고, 여러 개면 이 줄은 "완료 기준"만 두고 아래 하위 목록으로}
    - {완료 기준}

%% 반복: 체크한 분류마다, 메뉴 순서(1 → 6)로 — 그 분류 파일의 ③ 본문 뼈대 전체(# 분류명 ~ ### 세부 할 일)를 이 자리에 이어 붙인다 %%
{체크한 분류의 섹션}

%% 반복: 1단계에서 기타로 적은 일마다 — 분류 섹션들 뒤에. 기타가 없으면 이 블록 전체를 뺀다 %%
# 기타: {일 이름}

### 내용

- {무엇을 하는 일인지}
    - {세부 내용 / 지금까지 진행한 것}

### 세부 할 일

%% 반복: 세부 작업마다 — 4단계에서 확정한 순서대로 %%
- [ ] {작업} — {담당: 개요 담당자와 다를 때만} — {기한: 그 작업의 날짜를 말했을 때만}
````

## ④ 작성 메모

- 분류 속성 값은 고른 분류를 메뉴 순서로 쉼표로 나열한다. 기타를 골랐으면 `기타`를 넣고, 기타 일 이름은 본문 `# 기타:` 제목에만 쓴다.
- 본문 순서는 `# 개요` → 체크한 분류(메뉴 순서 1 → 6) → `# 기타:`. 사용자가 고른 순서가 아니라 메뉴 순서를 따른다.
- 분류 섹션 제목은 분류 이름 그대로 쓴다(예: `# 점검 문서 작성`). 노션에서 분류별로 찾기 쉽게 바꾸지 않는다.
- 세부 할 일은 Claude가 쪼갠 **제안**이다. 질문 모드에서는 4단계에서 확인받은 뒤 출력하고, 자료 모드에서는 바로 출력한 뒤 ③에 제안이라고 적는다. 제목에 `(제안)` 표시는 붙이지 않는다.
- 같은 작업을 두 분류에 중복해 넣지 않는다. 가장 가까운 분류 한 곳에만 넣는다.
    - 구조도를 그리는 작업 → 시스템 구조도 설계에만
    - 하드웨어 "동작 검증"과 점검 "점검 실시"가 같은 일이면(검증을 점검표로 하는 경우) → 점검 문서 작성에만
    - 시스템 설계와 구조도 설계의 "구성요소 정리" → 시스템 설계 내용 정리에만
- 본문 다른 섹션에 이미 단계가 나열되어 있으면(예: 제작 과정 1·2·3) 세부 할 일에서는 단계를 다시 쓰지 않고 "조립 (제작 과정 순서대로)"처럼 한 줄로 묶는다.
- 담당·기한은 지어내지 않는다. 모르면 쓰지 않는다(위 4단계 2번).
- 배경을 받지 못했으면 개요의 배경 줄을 뺀다. 목표·완료 기준은 필수라 비면 `⚠️ 확인 필요`로 둔다.
- 체크박스(`- [ ]`)는 노션에 붙여넣으면 할 일 블록으로 바뀐다. 따로 안내하지 않는다.
- 분류를 많이 골라 본문이 길어지면, 사용자가 원할 때 분류별로 할 일 페이지를 나눠 따로 출력할 수 있다(페이지마다 `# 개요`를 넣고 분류 속성은 하나만).
