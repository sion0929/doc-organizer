# 특허 초안 양식

- 유형: 1-1. 특허 초안(출원)
- 출력: 페이지
- 제목 수준: 섹션 `##` (구성요소 섹션도 같은 `##`), 섹션 안 소제목은 굵은 글씨 줄
- 용도: 우리 발명을 출원하기 위해 발명 내용을 정리한 초안(변리사 전달용). 이미 나온 특허를 읽고 비교하는 "선행특허 조사"(1-2)와 다르다.

## ① 노션 DB 속성

| 속성 | 종류 | 선택지 / 비고 |
|---|---|---|
| 발명 명칭 | 제목 | 국문 명칭 |
| 상태 | 선택 | 아이디어 / 초안 작성 / 발명신고 / 출원 / 등록 / 보류 |
| 발명자 | 사람 | 노션에서 직접 선택. 출력에는 이름만 적는다 |
| 관련 과제 | 선택 | 과제명 |
| 출원번호 | 텍스트 | 출원 후 받은 번호 그대로. 출원 전이면 `-` 로 두고 확인 필요로 세지 않는다 |
| 마감일 | 날짜 | 발명신고·출원 등 다음 마감 |

## ② 질문 목록

질문 모드에서는 SKILL.md의 왕복 줄이기 규칙대로 묶어서 묻는다. 권장 묶음(4번 왕복):

1. 1단계 + 2단계
2. 3단계 + 4단계 구성요소 목록
3. 구성요소별 질문 전부(한 메시지, 구성요소마다 짧은 하위 목록) + 5단계
4. 6단계 + 7단계

자료 모드에서는 비어 있는 **필수**만 묻는다.

### 1단계: 기본 정보
- **필수** 발명 명칭(국문)
- 선택: 영문 명칭 (없으면 Claude가 번역을 제안한다)
- 선택: 발명자, 관련 과제, 상태, 마감일, 출원번호

### 2단계: 발명의 배경
- **필수** 이 발명이 속한 기술 분야는?
- **필수** 기존 기술의 문제점은? (문제마다 한 줄씩)
- 선택: 이 발명을 개발하게 된 배경은?

### 3단계: 발명의 내용
- **필수** 문제를 해결하는 수단은? (수단마다 한 줄씩)
- 선택: 발명 전체 도면이 있나요? 무엇을 보여주는 그림인가요?
- 선택: 발명이 여러 상태(모드)로 나뉘나요? 상태별로 어떻게 되나요? (예: 대기 상태 / 작동 상태)

### 4단계: 구성요소
- **필수** 발명을 이루는 구성요소 목록과 각각의 도면부호는? (한 줄에 하나씩: 구성요소 이름 + 도면부호)
- 목록을 받은 뒤 **모든 구성요소에 대해 아래를 한 메시지에** 묻는다(구성요소마다 하위 목록으로).
    - 선택: 도면 — 이 구성요소를 보여주는 그림이 있나요? 무엇을 보여주나요?
    - **필수** 구성 — 무엇으로 이루어져 있나요? (하위 부품과 그 도면부호 포함)
    - **필수** 동작 원리 — 어떻게 작동하나요?
    - 선택: 의도한 효과 — 이 구성요소로 얻으려는 효과는?

### 5단계: 동작 과정
- **필수** 발명이 동작하는 순서는? (단계마다 단계 이름 + 설명)
- 선택: 동작 원리에 대해 보충할 설명은?

### 6단계: 발명의 효과
- **필수** 이 발명으로 얻는 효과는? (효과마다 한 줄씩)

### 7단계: 권리·용도·선행기술
- 선택: 주장하려는 권리(청구항)를 정해 둔 것이 있나요? 없으면 설명해주신 구성요소만으로 초안을 제안합니다.
- 선택: 이 발명을 어디에 쓸 수 있나요? (용도마다 한 줄씩)
- 선택: 알고 있는 선행기술이나 참고자료는? (특허번호, 논문, 링크)

## ③ 본문 뼈대

- `{ }` 는 채울 자리. 출력에서는 내용으로 바꾸거나 `➕ 추가 권장` 로 둔다.
- `%% 반복: … %%` 아래 블록은 개수만큼 반복, `%% 선택: … %%` 아래 블록은 내용이 없으면 통째로 뺀다.
- `%% … %%` 줄 자체는 출력하지 않는다.

````markdown

## 발명의 배경

{기술 분야: 이 발명이 속한 기술 분야와 그 분야에서 쓰이는 기술을 "…한다 / …이다" 문장으로 서술}

**기존 기술의 문제점**

%% 반복: 문제점마다 %%
````

## ④ 작성 메모

- 서술은 "…한다 / …이다" 문장으로 쓴다(번호 목록 항목 포함, 청구항 제외). 발명 명칭, `**상태명**`, `**단계명**`, `**용도**` 같은 이름 부분만 명사형으로 둔다.
- 영문 명칭을 사용자가 주지 않았으면 Claude가 번역을 제안하고 끝에 `(번역 제안)` 을 붙인다. 사용자가 준 영문 명칭은 그대로 쓴다.
- 도면부호는 받은 그대로 쓴다. 사용자가 주지 않은 도면부호를 새로 붙이지 않는다. 하위 부품의 도면부호를 모르면 본문에서는 `잠금 핀(➕ 추가 권장)` 처럼 쓴다.
- 기술 분야는 사용자가 말한 범위 안에서 1~2문장으로 쓴다. 그 분야의 일반 기술 설명을 지어 덧붙이지 않는다.
- 구성요소 이름과 도면부호는 문서 전체에서 하나로 통일한다(같은 부품을 다른 이름으로 부르지 않는다). 사용자가 쓴 이름을 그대로 쓴다.
- 구성요소 섹션은 4단계에서 받은 목록 순서대로, 목록에 있는 개수만큼 만든다. 섹션 제목은 `## 구성요소 이름 (도면부호)` 모양을 지킨다.
- 주장하려는 권리
    - 사용자가 청구항을 줬으면 표시 없이 그대로 쓴다. 내용을 바꾸지 않고, Claude가 항을 보태지 않는다. 더 필요해 보이면 ④ 따로 할 일에 제안한다.
    - 사용자가 주지 않았으면 Claude가 초안을 제안한다. 첫 줄에 `(초안 — 변리사 검토 필요)` 를 넣고, 사용자가 설명한 구성요소만 쓴다(새 구성요소·도면부호·효과를 지어내지 않는다).
    - 청구항 번호는 1부터 차례로 매긴다.
    - 청구항은 특허 관례대로 "…를 포함하는 ○○." 처럼 명사로 끝낸다. 아는 도면부호는 괄호로 붙이고, 모르는 도면부호는 `➕` 표시 없이 빼고 부품 이름만 쓴다.
- 발명의 효과는 기존 기술의 문제점과 짝이 맞는지 확인한다. 짝이 없는 문제점이 있으면 묻지 말고 ③ 확인할 것에 적는다. 사용자가 말하지 않은 효과를 보태지 않는다.
- 📷 줄은 사용자가 그림이 없다고 하면 뺀다. 있는지 모르면 남겨 둔다(노션에서 첨부할 자리). ④ 따로 할 일에 "노션에서 직접 첨부할 그림" 목록을 보여준다.
- 자료 모드에서 비어 있는 필수가 5개를 넘으면 다른 섹션이 기대는 항목(구성요소 목록·도면부호)부터 묻고, 나머지는 `➕ 추가 권장` 로 둔다.
- 노션 본문에는 문서 정리 페이지(`{파일명}_노션.md`)를 붙여넣고 전체 초안은 파일로 첨부한다: 📎 첨부 줄 → 전체 구성도 1장 → 구성요소별 핵심 구조·동작(간단한 그림 + 하는 일 / 진행 / 넘겨주는 것). SKILL.md "노션 페이지 구성".
- 선행기술의 자세한 분석(청구항 인용, 구성요소 비교)은 "선행특허 조사"(1-2) 페이지에 따로 쓴다. 여기에는 목록만 둔다.
