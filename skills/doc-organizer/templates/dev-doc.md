# 개발 문서 양식 (기술개발계획서)

- 유형: 3. 개발 문서
- 출력: 페이지 + md 초안 파일. 최종 제출본은 PDF이고, 이 양식은 그 **초안(md)** 을 만든다.
- 구조 출처: 한국로봇항공기경연대회 중급부문 기술개발계획서 양식(사용자 제공 PDF). 목차·절 구성·서술 방식만 옮겼다(내용은 없음).
- 제목 수준: 장 `#` (1.), 절 `##` (1-1.), 항 `###` (2-1-1.) — 노션 제목 3단계와 맞는다.
- 그림: 절마다 그림을 많이 넣는다. 특히 **시스템 구조도**와 **노드별 아키텍처**. 형식은 `templates/diagrams.md`.
    - 그림 아래에 캡션 한 줄: `그림 {번호} [ {제목} ]` (표는 `표 {번호} [ {제목} ]`). 번호는 문서 전체에서 차례로.

## ② 질문 목록

자료 모드(저장소, 설계서, 코드, 이전 계획서 등)가 기본이다. 자료로 초안을 **먼저** 쓰고, 빈 곳은 ③ 확인할 것에 적는다(SKILL.md 자료 모드).
질문 모드에서는 SKILL.md 왕복 줄이기 규칙대로 묶어서 묻는다.

### 1단계: 표지·개요
- **필수** 시스템 이름(약어면 풀이)과 한 줄 목표
- **필수** 임무 시나리오(단계 순서: 준비 → 이륙 → 임무 → 복귀 → 착륙, 실패 시 대응)
- 선택: 대회명·부문·소속·참가팀명·지도교수·대표자·제출일

### 2단계: 자동비행 시스템
- **필수** 소프트웨어 계층과 노드 목록(노드마다 역할 한 줄)
- **필수** 노드별 입력 / 처리 단계 / 출력 / 신뢰도·실패 처리 (자료에 있는 만큼)
- **필수** 하드웨어 구성품과 선정 근거
- 선택: 임무 장치와 수행 방법, GCS 구성, 통신(라우터·브리지)
- 선택: 시험 계획(시뮬레이션 → 실제 환경), 시험 항목

### 3단계: 특장점·안전·팀·일정
- 선택: 설계·제작상 특장점(창의성) 3–4개
- **필수** 안전장치 구성·성능·작동 확인 방법
- 선택: 지도교수·팀원(이름 / 소속·학년 / 역할) — 자료에 없으면 표만 두고 비운다
- 선택: 수행 체계와 추진 일정(월 단위)

## ③ 본문 뼈대

- `{ }` 는 채울 자리. 출력에서는 내용으로 바꾸거나 `⚠️ 확인 필요` 로 둔다.
- `%% 반복: … %%` 아래 블록은 개수만큼 반복, `%% 선택: … %%` 아래 블록은 내용이 없으면 통째로 뺀다.
- `%% … %%` 줄 자체는 출력하지 않는다.
- 문체: 제출 문서라서 이 유형만 **서술형 문장**("…한다", "…이다")으로 쓴다. 문단 2–4개, 필요하면 목록·표를 곁들인다.

## ④ 작성 메모

- **그림을 많이 넣는다.** 최소한 그림 1(전체 개념도), 그림 2(임무 시나리오), 그림 3(전체 S/W 아키텍처), 노드마다 개념도 1장, 시험 흐름도. 형식과 ChatGPT 이미지·Mermaid 사용법은 `templates/diagrams.md`.
- 노드 절(2-1-N)은 노드마다 같은 순서로 쓴다: 개념도 → 역할 한 줄 → 입력 → 처리 단계 → 출력 → 신뢰도·실패 처리. 자료에 없는 단계는 지어내지 않고 `⚠️ 확인 필요`.
- 노드 순서: S/W 아키텍처 그림의 계층 순서(인지 → 업무 수행 → 미션 관리 → 통신)를 따르고, 기체(시스템)가 여럿이면 기체별로 묶는다.
- 수치·토픽·알고리즘 이름은 자료 그대로. 설계서의 "기준안·예시값·TBD"는 그 표시를 문장에 남긴다(예: "운용 고도는 약 3 m(잠정)로 한다").
- 개발팀 현황(5장)은 개인정보라 자료에 없으면 표만 두고 빈 칸으로 둔다. 다른 문서(이전 계획서 등)에서 이름을 가져오지 않는다.
- 표지 속성은 ① 표로 출력하고, 본문에는 넣지 않는다.
- 사진(하드웨어, GCS 화면)은 📷 자리만 두고 ④에 "준비할 사진" 목록으로 알린다.
