# 논문 작성 양식

- 유형: 2-1. 논문 작성(투고 관리 겸용)
- 출력: 페이지 (논문 1편 = 페이지 1개. 버전이 바뀌어도 같은 페이지를 고쳐 쓴다)
- 제목 수준: 섹션 `###`, 내용은 들여쓰기 목록(최대 3단계)
- 용도: 쓰고 있는 논문의 개요(아웃라인)와 투고 진행 관리. 문장으로 쓴 원고가 아니라 들여쓰기 목록으로 된 뼈대다. 남의 논문을 읽고 정리하는 "논문 리뷰"(2-2)와 다르다.

## ① 노션 DB 속성

| 속성 | 종류 | 선택지 / 비고 |
|---|---|---|
| 논문 제목 | 제목 | 현재 작성본 제목 |
| 상태 | 선택 | 구상 / 작성 중 / 내부 검토 / 투고 / 리비전 / 게재 확정 / 게재 |
| 투고처 | 선택 | 학회·저널 이름 |
| 투고 마감일 | 날짜 | |
| 저자 | 텍스트 | 저자 순서대로, 쉼표로 구분. 연구실 밖 공저자도 적는다 |
| 관련 과제 | 선택 | 과제명 |
| 버전 | 텍스트 | 현재 작성본이 어느 버전인지. 예: 초안, 리비전 1 |

## ② 질문 목록

질문 모드에서는 단계 순서대로 한 번에 2~4개씩 묻는다. 자료 모드에서는 비어 있는 **필수**만 묻는다.

### 1단계: 기본 정보
- **필수** 지금 쓰고 있는 논문 제목 (가제도 된다)
- 선택: 이미 제출한 적이 있다면 버전별 이름과 그때 제목 (예: 초안 제출본)
- 선택: 상태, 투고처, 투고 마감일, 저자(순서대로), 관련 과제, 버전

### 2단계: 서론
- **필수** 연구 배경은? (왜 이 문제를 푸는지)
- **필수** 기존 방법들과 각각의 한계는?
- **필수** 제안하는 프레임워크를 한두 줄로 줄이면?
- **필수** 기여점은? (기여점마다 한 줄씩)

### 3단계: Problem Formulation
- **필수** 문제 환경과 주어진 조건(가정·입력)은?
- **필수** 목적은? (목표와 제약)
- 선택: 전체 프레임워크는 어떤 단계로 진행되나요? (순서대로)

### 4단계: 제안 방법
- **필수** 모듈(구성 부분)별 설명은? (모듈 이름 + 역할 + 세부 내용)
- 선택: 전체 구조도 그림이 있나요? 무엇을 보여주나요?

### 5단계: 실험
- **필수** 실험환경은? (시뮬레이터·하드웨어·데이터셋·주요 설정 등)
- **필수** 검증 실험마다 무엇을 검증하는지, 비교 대상, 평가 지표는?
- 선택: 실험환경·실험 결과 그림이 있나요? 무엇을 보여주나요?

### 6단계: 결론
- 선택: 결론으로 정리해 둔 내용이 있나요?

## ③ 본문 뼈대

- `{ }` 는 채울 자리. 출력에서는 내용으로 바꾸거나 `⚠️ 확인 필요` 로 둔다.
- `%% 반복: … %%` 아래 블록은 개수만큼 반복, `%% 선택: … %%` 아래 블록은 내용이 없으면 통째로 뺀다.
- `%% … %%` 줄 자체는 출력하지 않는다.

````markdown
### 제목

%% 반복: 버전마다 한 항목, 오래된 것부터. 그 사이 버전(예: 리비전 제출본)은 "현재 작성본" 앞에 같은 모양으로 넣고, 아직 제출 전이면 "현재 작성본"만 남긴다 %%
- 초안 제출본
    - {처음 제출할 때의 논문 제목}
- 현재 작성본
    - {지금 쓰고 있는 논문 제목}

### 서론

- 연구배경
    - {연구 배경 요점}
- 기존 방법 및 한계
    - 기존 방법들
        - {기존 방법}: {핵심 아이디어}
    - 한계
        - {기존 방법들의 한계}
- 제안 프레임워크 개요
    - {제안 프레임워크 요점}
- 기여점
    - {기여점}

### Problem Formulation

- 문제 환경·주어진 조건
    - {환경 / 가정 / 주어진 입력}
- 목적
    - 목표: {달성하려는 것}
    - 제약: {지켜야 할 조건}
- 전체 프레임워크 단계
    1. {단계 이름}: {이 단계에서 하는 일}

### 제안 방법

📷 [그림: 전체 구조도 — 노션에서 직접 첨부]

%% 반복: 모듈마다 %%
- {모듈 이름}
    - {역할 / 입력과 출력}
        - {세부 내용}

### 실험

- 실험환경
    - {시뮬레이터 / 하드웨어 / 데이터셋 / 주요 설정}
    - 📷 [그림: {실험 환경 — 무엇을 보여주는지} — 노션에서 직접 첨부]

%% 반복: 검증 실험마다 %%
- {검증 실험: 무엇을 검증하는지}
    - 📷 [그림: {실험 결과 그래프·표} — 노션에서 직접 첨부]
    - 비교 대상: {비교할 방법}
    - 평가 지표: {지표}

%% 선택: 결론을 정리해 둔 경우 %%
### 결론

- {결론 요점}
````

## ④ 작성 메모

- 문장으로 풀어 쓰지 않는다. 짧은 개조식 들여쓰기 목록으로 쓴다.
- 들여쓰기는 공백 4칸씩, 최대 3단계(`-` → 공백 4칸 → 공백 8칸)까지. 더 깊어지면 위 항목을 둘로 쪼갠다.
- `{ }` 로 된 맨 아래 항목은 요점 개수만큼 같은 수준으로 늘린다(기존 방법, 한계, 기여점, 프레임워크 단계 등).
- 섹션 이름은 바꾸지 않는다. "Problem Formulation" 은 영어 그대로 둔다.
- 방법 이름·모델 이름·데이터셋·지표 이름 같은 전문 용어는 사용자가 쓴 표기 그대로 쓴다(영어면 영어).
- 수식은 인라인 코드로 쓴다. `$$` 수식 블록은 쓰지 않는다.
- 제목 섹션
    - 제출할 때마다 그때 제목을 남기고 "현재 작성본"만 고친다. 이전 버전 제목을 지우지 않는다.
    - 노션 속성 "논문 제목"은 현재 작성본 제목과 같게 쓴다.
- 기존 방법을 쓸 때 논문 이름·저자·연도는 사용자가 준 것만 쓴다. 서지 정보를 지어내지 않는다.
- 실험 결과 수치는 받은 그대로 쓴다. 아직 실험 전이면 계획만 쓰고 결과를 짐작해 채우지 않는다.
- 📷 줄은 사용자가 그림이 없다고 하면 뺀다. 있는지 모르면 남겨 둔다(노션에서 첨부할 자리). ④ 따로 할 일에 "노션에서 직접 첨부할 그림" 목록을 보여준다.
- 투고 관리 겸용이다. 사용자가 이전에 정리한 노션 페이지 내용을 붙여넣으면 그것을 자료로 삼아 바뀐 부분을 반영하고 전체를 다시 출력한다.
