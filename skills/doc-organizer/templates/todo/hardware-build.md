# 할 일 분류 양식: 하드웨어 제작 내용 정리

- 분류: 7. 할 일 → 2. 하드웨어 제작 내용 정리
- 섹션 제목: `# 하드웨어 제작 내용 정리`, 하위 항목 `###`
- 위치: 할 일 본문(`todo.md` ③)의 `# 개요` 뒤. 다른 분류와 함께 고르면 메뉴 순서대로 이어 붙인다.
- DB 속성: `todo.md`의 ① 표를 쓴다(이 파일에는 없다). 분류 속성에 `하드웨어 제작 내용 정리`를 넣는다.
- 용도: 하드웨어(기구물·전장·시제품 등)를 만드는 과정과 결과를 사양 → 부품 → 제작 → 검증 순서로 한곳에 정리한다.

## ② 질문 목록

`todo.md` 3단계에서 이 분류 차례가 오면 아래 순서대로 묻는다. 질문 모드는 한 번에 2~4개씩, 자료 모드는 비어 있는 **필수**만 묻는다.
개요(`todo.md` 2단계)에서 이미 받은 답으로 채워지는 질문은 다시 묻지 않는다.

### 3-1단계: 목적·사양
- **필수** 무엇을 만드나요? 어디에 쓰나요? (개요의 목표로 충분하면 생략)
- **필수** 정해진 사양은? (크기·무게·전원·성능 등, 값과 단위. 아직 안 정했으면 "미정")

### 3-2단계: 부품
- **필수** 들어가는 부품은? (부품명·규격·수량)
- 선택: 부품별 비고는? (구매 필요 / 재고 있음 / 대체품 등)

### 3-3단계: 제작 과정
- 선택: 제작 단계는? (한 것과 할 것)
- 선택: 조립·배선에서 기억해둘 점은? (순서, 연결 지점, 주의점)
- 선택: 도면·사진·CAD 파일이 있나요? (파일명)

### 3-4단계: 문제·검증
- 선택: 제작 중 생긴 문제와 해결 방법은? (해결 안 된 것 포함)
- 선택: 어떻게 검증했나요(또는 할 건가요)? 결과는?
- 선택: 지금 어디까지 진행됐나요? (끝난 세부 할 일을 체크하는 데 쓴다)

## 세부 할 일 쪼개기 기준

`todo.md` 4단계에서 이 기준과 사용자의 답으로 세부 할 일을 제안한다.

**기본 순서**

1. 사양 확정 — 크기·전원·성능 등 정해야 할 값 정리
2. 부품 목록·구매 요청 — 부품 표 작성, 없는 부품 구매 요청
3. 도면 작성 — 기구 도면·CAD, 배선도
4. 가공·출력 — 부품별 가공(예: 3D 프린팅, 절삭)
5. 조립·배선 — 기구 조립, 전선·커넥터 연결
6. 동작 검증 — 검증 항목별 시험
7. 문서화 — 이 섹션 완성, 도면·사진·파일 첨부

**답에 맞춰 바꾸기**

- 작업 이름에 답에 나온 대상을 넣는다(예: "가공·출력: {부품명}", "동작 검증: {검증 항목}").
- 사양이 `미정`이면 "사양 확정"을 첫 작업으로 두고, 정할 사양 항목을 하위 체크박스로 나눈다.
- 구매할 부품이 없으면 "구매 요청"을 빼고 "부품 목록 확인"만 둔다. 구매할 부품이 있으면 "구매 요청(구매물품 양식으로 정리)"으로 둔다.
- 가공할 부품이 여럿이면 부품(또는 가공 방법)별로 나눈다.
- 전장이 없는 기구물이면 배선을 빼고 "조립"만 둔다. 기구 없이 회로만 만들면 "가공·출력" 대신 "기판·배선 제작"으로 바꾼다.
- 검증 항목이 여럿이면 "동작 검증" 아래 항목별 하위 체크박스로 나눈다.
- 해결 안 된 문제가 있으면 "문제 해결: {문제}"를 관련 단계 바로 뒤에 넣는다.
- 이미 끝난 단계는 `- [x]`로 남긴다.

## ③ 본문 뼈대

- `{ }` 는 채울 자리. 출력에서는 내용으로 바꾸거나 `⚠️ 확인 필요` 로 둔다.
- `%% 반복: … %%` 아래 블록은 개수만큼 반복, `%% 선택: … %%` 아래 블록은 내용이 없으면 통째로 뺀다.
- `%% … %%` 줄 자체는 출력하지 않는다.

````markdown
# 하드웨어 제작 내용 정리

### 제작 목적·사양

- 목적: {무엇을 위해 만드는지}
- 사양
    - {사양 항목}: {값·단위}

### 부품

%% 반복: 표의 행은 부품마다 %%
| 부품 | 규격 | 수량 | 비고 |
|---|---|---|---|
| {부품명} | {규격·모델명} | {수량} | {구매 필요 / 재고 / 대체품 등} |

%% 선택: 도면·사진·파일이 있을 때 %%
### 도면·사진

- 📷 [그림: {도면 / 제작 중·완성 사진} — 노션에서 직접 첨부]
- 📎 [파일: {CAD·도면 파일명} — 노션에서 직접 첨부]

%% 선택: 제작 단계를 말했을 때 %%
### 제작 과정

%% 반복: 제작 단계마다 %%
1. {제작 단계}
    - {세부 내용 / 사용한 장비·공구 / 설정값}

%% 선택: 조립·배선 메모가 있을 때 %%
### 조립·배선 메모

%% 반복: 메모마다 %%
- {조립 순서·주의점 / 배선: 연결 지점 → 연결 지점}

%% 선택: 문제가 있었을 때 %%
### 문제와 해결

%% 반복: 문제마다 %%
- 문제: {발생한 문제}
    - 원인: {원인}
    - 해결: {해결 방법 / 해결 안 됨}

%% 선택: 검증을 했을 때 %%
### 검증 결과

%% 반복: 검증 항목마다 %%
- {검증 항목}: {결과 / 수치·단위}
    - 📷 [그림: {검증 장면·결과 그래프} — 노션에서 직접 첨부]

### 세부 할 일

%% 반복: 세부 작업마다 — todo.md 4단계에서 확정한 순서대로 %%
- [ ] {세부 작업} — {담당} — {기한}
````

## ④ 작성 메모

- 목적이 개요의 목표와 같으면 한 줄로 줄이고, 이 섹션은 사양 위주로 쓴다.
- 사양은 항목마다 하위 목록 한 줄씩 쓴다. 아직 정하지 않은 사양은 값 자리에 `미정`으로 쓴다(모르는 값 `⚠️ 확인 필요`와 구분).
- 부품명·규격·모델명·수량은 받은 그대로 쓴다(대소문자·하이픈 포함). 규격을 모르면 `⚠️ 확인 필요`.
- 부품 표에는 가격을 넣지 않는다. 구매가 필요한 부품이 있으면 출력 뒤 "구매물품(유형 6)으로도 정리할까요?"라고 한 번 묻는다.
- 핀 번호·커넥터 이름·설정값·파일명은 인라인 코드(`` ` ``)로 감싼다.
- 도면·사진·CAD 파일은 붙여넣기로 들어가지 않는다. 자리 표시만 남기고, 출력 뒤 "노션에서 직접 첨부할 파일" 목록을 따로 보여준다. 없는 자리 표시 줄은 뺀다.
- 문제의 원인이 확실하지 않으면 사용자가 쓴 확신 정도("의심됨" 등)를 그대로 살린다. "해결 안 됨"인 문제는 세부 할 일에 해결 작업으로 넣는다.
- 세부 할 일의 제안 표시와 담당·기한 규칙은 `todo.md` 4단계와 ④를 따른다.
