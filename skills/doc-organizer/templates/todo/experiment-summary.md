# 할 일 분류 양식: 실험 내용 정리

- 분류: 7. 할 일 → 1. 실험 내용 정리
- 섹션 제목: `# 실험 내용 정리`, 하위 항목 `###`
- 위치: 할 일 본문(`todo.md` ③)의 `# 개요` 뒤. 다른 분류와 함께 고르면 메뉴 순서대로 이어 붙인다.
- DB 속성: `todo.md`의 ① 표를 쓴다(이 파일에는 없다). 분류 속성에 `실험 내용 정리`를 넣는다.
- 용도: 여러 날에 걸친 시험(시험일지 여러 개)을 묶어 **실험 전체를 종합**한다. 하루(한 번) 시험의 기록은 시험일지(유형 4)로 쓴다.

## ② 질문 목록

`todo.md` 3단계에서 이 분류 차례가 오면 아래 순서대로 묻는다. 질문 모드는 한 번에 2~4개씩, 자료 모드는 비어 있는 **필수**만 묻는다.
개요(`todo.md` 2단계)에서 이미 받은 답으로 채워지는 질문은 다시 묻지 않는다.

### 3-1단계: 목적·가설
- **필수** 이 실험으로 확인하려는 것은? (개요의 목표로 충분하면 생략)
- 선택: 예상하는 결과(가설)는?

### 3-2단계: 구성·절차
- **필수** 사용한 장비와 환경은? (장비·센서·플랫폼, 장소·조건)
- 선택: 시험 시나리오는? (시나리오가 여러 개면 각각)
- 선택: 실험 절차는? (순서대로)

### 3-3단계: 평가 지표·결과
- **필수** 무엇으로 평가하나요? (지표 이름, 측정 방법, 단위)
- **필수** 조건별 결과는? (조건 × 지표마다 수치·판정. 아직 안 한 조건은 "미실시")
- 선택: 결과 그래프나 비교 그림이 있나요?

### 3-4단계: 결론·관련 시험일지
- **필수** 이 실험에 포함된 시험일지는? (날짜와 시험일지 제목)
- 선택: 결론과 다음 단계는? (가설이 맞았는지, 추가 실험·개선할 점)
- 선택: 지금 어디까지 정리했나요? (끝난 세부 할 일을 체크하는 데 쓴다)

## 세부 할 일 쪼개기 기준

`todo.md` 4단계에서 이 기준과 사용자의 답으로 세부 할 일을 제안한다.

**기본 순서**

1. 관련 시험일지 모으기 — 실험에 포함된 시험일지 날짜·제목 목록 만들기
2. 조건·지표 정리 — 비교할 조건과 평가 지표 확정
3. 결과 데이터 정리 — 시험일지·로그에서 조건별 수치를 뽑아 결과 표 채우기
4. 그래프·그림 작성 — 결과 비교 그래프, 실험 구성 사진 고르기
5. 빠진 데이터 확인 — 비어 있는 조건, 다시 해야 할 시험 찾기
6. 결론·다음 단계 작성 — 가설과 비교해 결론 쓰기
7. 검토·공유 — 팀 검토 받고 노션에 올리기

**답에 맞춰 바꾸기**

- 작업 이름에 답에 나온 대상을 넣는다(예: "결과 데이터 정리: {조건 이름}", "그래프 작성: {지표 이름}").
- 결과 표에 `미실시` 조건이 있으면 "추가 시험: {조건}"을 조건마다 넣는다(그 시험의 기록은 시험일지로 따로 쓴다).
- 조건이나 지표가 많으면 "결과 데이터 정리"를 조건(또는 지표)별 하위 체크박스로 나눈다.
- 가설이 아직 없으면 "가설 정리"를 맨 앞에 넣는다.
- 그래프·그림이 필요 없으면 4를 뺀다.
- 이미 끝난 단계는 `- [x]`로 남긴다.

## ③ 본문 뼈대

- `{ }` 는 채울 자리. 출력에서는 내용으로 바꾸거나 `⚠️ 확인 필요` 로 둔다.
- `%% 반복: … %%` 아래 블록은 개수만큼 반복, `%% 선택: … %%` 아래 블록은 내용이 없으면 통째로 뺀다.
- `%% … %%` 줄 자체는 출력하지 않는다.

````markdown
# 실험 내용 정리

### 목적·가설

- 목적: {이 실험으로 확인하려는 것}
- 가설: {예상하는 결과}

### 구성

- 장비: {사용한 장비·센서·플랫폼}
- 환경: {장소 / 조건}
- 시나리오: {시험 시나리오}
    - {시나리오별 세부 설명}
- 📷 [그림: {실험 구성·환경} — 노션에서 직접 첨부]

%% 선택: 절차를 말했을 때 %%
### 절차

%% 반복: 절차 단계마다 %%
1. {절차 단계}
    - {세부 내용 / 반복 횟수 / 설정값}

### 평가 지표

%% 반복: 지표마다 %%
- **{지표 이름}**: {정의 / 측정 방법 / 단위}

### 결과 종합

%% 반복: 표의 행은 조건 × 지표 조합마다 %%
| 조건 | 지표 | 결과 |
|---|---|---|
| {조건} | {지표} | {결과 수치·단위 / 판정 / 미실시} |

- {결과에서 보이는 경향 / 특이 사항}
- 📷 [그림: {결과 비교 그래프} — 노션에서 직접 첨부]

%% 선택: 결론이나 다음 단계를 말했을 때 %%
### 결론·다음 단계

- 결론: {가설이 맞았는지 / 알게 된 것}
- 다음 단계: {추가 실험 / 개선할 점}

### 관련 시험일지

%% 반복: 시험일지마다 — 날짜순 %%
- {시험일} {시험일지 제목}

### 세부 할 일

%% 반복: 세부 작업마다 — todo.md 4단계에서 확정한 순서대로 %%
- [ ] {작업} — {담당: 개요 담당자와 다를 때만} — {기한: 그 작업의 날짜를 말했을 때만}
````

## ④ 작성 메모

- 시험일지는 하루 기록, 이 분류는 실험 전체 종합이다. 하루 단위의 세부 로그·파일 목록은 옮겨 적지 않고, "관련 시험일지"에 날짜·제목만 남긴다.
- 관련 시험일지는 `- YYYY-MM-DD 시험일지 제목` 형식으로 날짜순으로 쓴다. ④ 따로 할 일에 "노션에 붙여넣은 뒤 각 줄에 `@`로 해당 시험일지 페이지를 멘션하면 연결된다"고 한 줄로 알려준다.
- 시험 전이라 시험일지가 아직 없으면 관련 시험일지에 `- 아직 없음` 한 줄만 둔다.
- 결과 표의 수치·단위·조건 이름은 받은 그대로 쓴다. 한 칸에 한 값만 쓰고 칸 안에서 줄을 바꾸지 않는다(칸 안 `|`는 `/`로).
- 아직 하지 않은 조건은 결과 칸에 `미실시`로 쓴다. 결과를 모르는 것(`⚠️ 확인 필요`)과 구분한다.
- 결론은 사용자가 말한 것만 쓴다. 결과 표를 보고 가설이 맞았다고 Claude가 판단해 쓰지 않는다.
- 가설이 없으면 가설 줄을, 시나리오가 하나뿐이면 하위 목록을, 그림이 없으면 📷 줄을 뺀다.
- 세부 할 일의 제안 표시와 담당·기한 규칙은 `todo.md` 4단계와 ④를 따른다.
