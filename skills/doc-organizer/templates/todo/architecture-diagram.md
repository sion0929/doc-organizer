# 할 일 분류 양식: 시스템 구조도 설계

- 분류: 7. 할 일 → 5. 시스템 구조도 설계
- 섹션 제목: `# 시스템 구조도 설계`, 하위 항목 `###`
- 위치: 할 일 본문(`todo.md` ③)의 `# 개요` 뒤. 다른 분류와 함께 고르면 메뉴 순서대로 이어 붙인다.
- DB 속성: `todo.md`의 ① 표를 쓴다(이 파일에는 없다). 분류 속성에 `시스템 구조도 설계`를 넣는다.
- 용도: 시스템 구조도를 그리기 위해 범위 → 구성요소 → 연결을 표로 정리하고, 최종 구조도 그림을 붙인다. 설계 이유·요구사항은 "시스템 설계 내용 정리" 분류로 쓴다.

## ② 질문 목록

`todo.md` 3단계에서 이 분류 차례가 오면 아래 순서대로 묻는다. 질문 모드는 한 번에 2~4개씩, 자료 모드는 비어 있는 **필수**만 묻는다.
개요(`todo.md` 2단계)에서 이미 받은 답으로 채워지는 질문은 다시 묻지 않는다.

### 3-1단계: 범위
- **필수** 어떤 시스템(또는 서브시스템)의 구조도인가요?
- 선택: 일부러 빼고 그릴 부분은?
- 선택: 어느 수준까지 그리나요? (예: 큰 블록 수준 / 모듈 수준)

### 3-2단계: 구성요소
- **필수** 구조도에 들어갈 구성요소와 각각의 역할은?
- **필수** 구성요소마다 종류는? (HW / SW / 통신)

### 3-3단계: 연결
- **필수** 무엇이 무엇으로, 어떤 데이터·신호를, 어떤 방식으로 보내나요? (출발 → 도착 / 데이터·신호 / 방식)
    - 모르는 구간이 있으면 "모름"으로 받고 세부 할 일에 확인 작업으로 넣는다.

### 3-4단계: 그림
- 선택: 최종 구조도는 무엇으로 그리나요? 원본 파일이 있나요? (도구·파일명)
- 선택: 지금 어디까지 진행됐나요? (끝난 세부 할 일을 체크하는 데 쓴다)

## 세부 할 일 쪼개기 기준

`todo.md` 4단계에서 이 기준과 사용자의 답으로 세부 할 일을 제안한다.

**기본 순서**

1. 범위·상세 수준 정하기 — 무엇을 어디까지 그릴지 확정
2. 구성요소 목록 확정 — 구성요소 표 채우기(이름·종류·역할)
3. 연결 정리 — 연결 표 채우기(출발·도착·데이터·신호·방식)
4. 초안 그리기 — Mermaid 초안 또는 손그림으로 배치 잡기
5. 팀 검토 — 빠진 구성요소·연결 확인, 의견 반영
6. 최종 구조도 작성 — 그리기 도구로 완성, 노션에 그림 첨부

**답에 맞춰 바꾸기**

- 작업 이름에 답에 나온 대상을 넣는다(예: "연결 확인: {구성요소} → {구성요소}", "구조도 작성: {서브시스템}").
- 연결을 "모름"이라고 한 구간마다 "연결 확인: {구간}" 작업을 3 안에 하위 체크박스로 넣는다.
- 서브시스템이 많거나 한 장에 다 들어가지 않으면 4·6을 서브시스템별로 나눈다(전체 구조도 1장 + 서브시스템 구조도).
- "시스템 설계 내용 정리"도 함께 골랐으면 구성요소 이름을 그 섹션과 맞추고, 요구사항·설계 결정 작업은 그쪽에만 넣는다.
- 이미 끝난 단계는 `- [x]`로 남긴다.

## ③ 본문 뼈대

- `{ }` 는 채울 자리. 출력에서는 내용으로 바꾸거나 `⚠️ 확인 필요` 로 둔다.
- `%% 반복: … %%` 아래 블록은 개수만큼 반복, `%% 선택: … %%` 아래 블록은 내용이 없으면 통째로 뺀다.
- `%% … %%` 줄 자체는 출력하지 않는다.

````markdown

- 대상: {구조도로 그릴 시스템 / 서브시스템}

- 제외: {그리지 않을 부분}
- 상세 수준: {큰 블록 수준 / 모듈 수준 등}

### 구성요소
````

## ④ 작성 메모

- 구성요소 이름은 구성요소 표·연결 표·Mermaid·세부 할 일에서 글자 하나까지 똑같이 쓴다.
- 종류는 `HW` / `SW` / `통신` 중 하나로 쓴다. 어느 쪽인지 애매하면 사용자에게 묻는다.
- 연결 표의 출발·도착에는 구성요소 표에 있는 이름만 쓴다. 표에 없는 이름이 나오면 구성요소 표에 행을 추가하고 확인받는다.
- 연결을 모르는 구간은 데이터·신호나 방식 칸을 `⚠️ 확인 필요`로 두고, 세부 할 일에 "연결 확인" 작업을 넣는다.
- 범위의 제외·상세 수준을 답하지 않았으면 그 줄을 뺀다. 원본 파일이 없으면 📎 줄을 뺀다.
- 다이어그램은 기본으로 그린다(사용자 요청: 아키텍처를 많이). 형식·색·Mermaid 규칙·ChatGPT 이미지 사용법은 `templates/diagrams.md` 를 따른다. 연결 표에 없는 연결을 지어내지 않는다.
- 최종 구조도는 그리기 도구로 만든 그림을 노션에 직접 첨부한다(📷 자리 표시). ④ 따로 할 일에 "노션에서 직접 첨부할 파일" 목록을 보여준다.
- 세부 할 일의 제안 표시와 담당·기한 규칙은 `todo.md` 4단계와 ④를 따른다.
