# 시험일지 양식

- 유형: 4. 시험일지
- 출력: 페이지
- 제목 수준: 섹션 `#`, 하위 항목 `###`
- 용도: 하루(한 번) 시험의 기록. 실험 전체를 종합하는 "실험 내용 정리"(할 일 분류)와 다르다.

## ① 노션 DB 속성

| 속성 | 종류 | 선택지 / 비고 |
|---|---|---|
| 시험명 | 제목 | 예: 날짜 + 시험 대상 + 시험 목적을 짧게 |
| 시험일 | 날짜 | |
| 장소 | 텍스트 | |
| 참여자 | 사람 | 노션에서 직접 선택. 출력에는 이름만 적는다 |
| 관련 과제 | 선택 | 과제명 |
| 시험 대상 시스템 | 다중 선택 | 시험한 서브시스템들 |
| 결과 | 선택 | 성공 / 부분 성공 / 실패 |

## ② 질문 목록

질문 모드에서는 단계 순서대로 한 번에 2~4개씩 묻는다. 자료 모드에서는 비어 있는 **필수**만 묻는다.

### 1단계: 기본 정보
- **필수** 시험명(또는 무엇을 시험했는지 한 줄)
- **필수** 시험일
- 선택: 장소, 참여자, 관련 과제

### 2단계: 시험내용
- **필수** 이번에 시험한 항목들은? (항목별로 한 줄씩)
- 선택: 항목별 세부 내용이나 지난번과 달라진 점은?

### 3단계: 시험결과
- **필수** 서브시스템(또는 시험 항목)별 결과는? 성공/실패, 관찰한 현상, 수치
- 선택: 서브시스템별 결론, 참고한 링크, 남겨둔 사진·영상
- 시험 대상 시스템과 결과(성공/부분 성공/실패) 속성은 결과를 보고 Claude가 채우고 ③ 확인할 것에 제안값으로 적는다(이것만을 위해 묻지 않는다).

### 4단계: 분석
- 선택: 문제의 원인으로 보이는 것, 로그·그래프에서 확인한 것은?

### 5단계: TODO
- 선택: 다음 시험 날짜와 계획은? 안 될 경우의 차선책은?

### 6단계: LOG
- 선택: 남긴 데이터 파일은? (rosbag, ulog, 영상 등 종류별 파일명)

## ③ 본문 뼈대

- `{ }` 는 채울 자리. 출력에서는 내용으로 바꾸거나 `⚠️ 확인 필요` 로 둔다.
- `%% 반복: … %%` 아래 블록은 개수만큼 반복, `%% 선택: … %%` 아래 블록은 내용이 없으면 통째로 뺀다.
- `%% … %%` 줄 자체는 출력하지 않는다.

````markdown
# 시험내용

%% 반복: 시험 항목마다 %%
- {시험 항목}
    - {세부 내용 / 지난번과 달라진 점}

# 시험결과

%% 반복: 서브시스템(시험 항목)마다 %%
### {서브시스템 이름}

- {결과 / 관찰한 현상 / 수치}
    - {세부 설명}
- 📷 [그림: {무엇을 보여주는지} — 노션에서 직접 첨부]
- 참고: [{링크 설명}]({URL})
- 결론: {이 서브시스템에 대한 한 줄 결론}

%% 선택: 분석할 내용이 있을 때 %%
# 분석

%% 반복: 발견 사항마다 %%
- {발견 사항}
    - {근거: 로그·그래프에서 확인한 것}
    - 📷 [그림: {그래프·로그 설명} — 노션에서 직접 첨부]

%% 선택: 다음 계획이 있을 때 %%
# TODO

{다음 시험 날짜} 실험 계획

- {할 일}
    - 안 될 경우: {차선책}

%% 선택: 남긴 데이터가 있을 때 %%
# LOG

%% 반복: 데이터 종류마다 %%
- {데이터 종류: rosbag / ulog / 영상 등}
    - 📎 [파일: {파일명} — 노션에서 직접 첨부]
````

## ④ 작성 메모

- 결과에 나온 수치·토픽 이름·파라미터·파일명은 받은 그대로 쓴다(대소문자, 밑줄 포함).
- 토픽·명령어·파일 경로는 인라인 코드(`` ` ``)로 감싼다.
- 시험결과의 "결론:" 줄은 사용자가 결론을 말했을 때만 쓴다. 결론이 없으면 그 줄을 뺀다(지어내지 않는다).
- 원인이 확실하지 않은 내용은 분석에 "의심됨" "추정"처럼 사용자가 쓴 확신 정도를 그대로 살린다.
- 사진·영상·로그 파일은 붙여넣기로 들어가지 않는다. 자리 표시만 남기고, ④ 따로 할 일에 "노션에서 직접 첨부할 파일" 목록을 보여준다.
- 사진이 어느 서브시스템 것인지 알면 그 서브시스템의 시험결과에, 모르면 LOG에 `- 사진` 항목으로 넣는다. 무엇을 찍었는지 모르면 `📷 [그림: 사진 1 — 노션에서 직접 첨부]` 처럼 번호만 붙인다.

## ⑤ 로그 그래프 (PlotJuggler)

자료나 답에 PX4 로그(`.ulg`) 경로가 있으면, 문제가 된 구간의 그래프를 PlotJuggler로 열고 계산한 수치를 분석에 넣는다.
스크립트: `<이 Skill 폴더>/scripts/pj_layout.py` (pyulog·numpy로 로그를 읽어 문제 구간을 찾고 PlotJuggler 레이아웃 XML을 만든다).

### 1. 도구 확인과 설치 허락

```bash
python3 <이 Skill 폴더>/scripts/pj_layout.py --check
```

- `"missing": []` → 2로 간다.
- 빠진 것이 있으면 **설치하기 전에 허락을 받는다**(질문 도구가 있으면 `설치` / `로그 그래프 생략` 선택 칸). 다른 질문과 같은 메시지에 묶어도 된다.
    - `pyulog`, `numpy` → 허락하면 Claude가 `pip install --user pyulog numpy` 실행
    - `plotjuggler` → sudo가 필요하다. 사용자에게 입력창에서 직접 실행하도록 안내한다:
      ROS가 있으면 `! sudo apt install ros-$ROS_DISTRO-plotjuggler-ros`, 없으면 `! sudo snap install plotjuggler`
- 사용자가 설치하지 않겠다고 하면 **로그 그래프와 로그 수치를 생략**한다. 분석의 📷 그래프 자리, ④의 PlotJuggler 안내도 넣지 않는다. LOG 섹션의 파일 목록은 그대로 둔다.

### 2. 어느 축을 볼지

시험결과·분석에 나온 문제로 정한다: "롤" → `roll`, "피치" → `pitch`, "요" "헤딩" → `yaw`, 축을 말하지 않았으면(예: "진동", "흔들림") `all`(스크립트가 오차가 가장 큰 축을 고른다).

### 3. 레이아웃 만들고 열기

로그마다 실행한다(3개 넘으면 어느 로그를 볼지 묻는다).

```bash
python3 <이 Skill 폴더>/scripts/pj_layout.py <로그.ulg> --axis <축> --out ~/notion-output/<문서 파일명>_plotjuggler/<로그 이름>.xml --open
```

- PlotJuggler 창이 로그마다 열린다. 탭 두 개: **문제 구간**(오차가 가장 큰 구간 확대) / **전체 비행**.
- 그래프 세 개: 모터 출력(`actuator_motors`), 각속도 목표·실제(`vehicle_rates_setpoint` / `vehicle_angular_velocity`, rad/s), 자세 목표·실제(쿼터니언에서 계산한 deg).
- 표준출력의 JSON 요약을 분석에 쓴다. 이착륙 앞뒤 3초는 문제 구간 찾기에서 뺀다(`--trim`).

### 4. 분석에 넣는 방법

JSON 요약의 값만 쓴다(지어내지 않는다). 로그마다 발견 사항 하나:

````markdown
- {축 이름} 각속도 추종 오차가 가장 큰 구간: {problem_window_s 시작}–{끝}초 (`{로그 이름}`)
    - 오차 RMS {worst_window} deg/s (이착륙 제외 비행 전체 {flight})
    - 모터 출력 흔들림(표준편차) {motors_in_window 의 std 범위}
    - 📷 [그림: {로그 이름} 문제 구간 — 모터 출력·{축 이름} 각속도·{축 이름} 자세 (PlotJuggler) — 노션에서 직접 첨부]
````

- `osc_peak_hz_above_2hz` 가 있으면 `- 2 Hz 이상에서 가장 큰 진동 주파수 약 {값} Hz (로그 기록 주기 {gyro_log_rate_hz} Hz 기준)` 한 줄을 더한다. `null` 이면 쓰지 않는다.
- 로그가 둘 이상이면 마지막에 비교 한 줄: `- {로그A} → {로그B}: 문제 구간 오차 RMS {a} → {b} deg/s`
- 수치의 해석(원인 추정)은 사용자가 말한 범위에서만 쓴다. 예: 사용자가 "튜닝 후 정상으로 들어옴"이라고 했으면 수치가 그것을 뒷받침하는지만 적는다.

### 5. ④ 따로 할 일에 넣을 것

- `PlotJuggler 창이 로그마다 열려 있습니다. "문제 구간" 탭을 캡처해서 분석의 📷 자리에 붙여넣으세요.`
- 다시 열 때 쓸 명령: `plotjuggler -d <로그.ulg> -l <레이아웃.xml>`
